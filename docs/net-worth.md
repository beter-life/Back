# MDL 6 — Net Worth / Patrimônio

## Model and boundaries

Per currency: accountAssets + manualAssets - accountLiabilities - manualLiabilities.
Positive/negative account balances determine asset/liability, not account type.
Inactive accounts remain included; zero is neutral. Accounts use existing MDL2
initial + uncancelled income - expenses - outgoing + incoming transfers, read-only.
No snapshots, FX, forecasts, jobs, yield/debt planning or writes to MDL2–MDL5.

`asOf` is YYYY-MM-DD, valid years 1000–9998, not future; omitted uses profile today,
UTC fallback. Movements must precede next local midnight (DST-aware PostgreSQL
AT TIME ZONE). Opening balances enter history only after account creation because
MDL2 has no separate economic opening date. Historical positions are derived from
current metadata and existing ledger; cancelled entries are excluded retroactively.

## Manual items and valuations

`app.financial_net_worth_items`: owner, name/description, immutable kind/currency,
kind-compatible category, ACTIVE/ARCHIVED, timestamps. No mutable current value.
ASSET categories PROPERTY/VEHICLE/BUSINESS/VALUABLE/OTHER; LIABILITY categories
MORTGAGE/LOAN/FINANCING/OTHER. Patch only name, description, category.

`app.financial_net_worth_valuations`: compound item+owner FK, value_minor BIGINT,
valuation_date DATE, optional note, created_at. Create item + positive first value
atomically. Later observations may be zero, never negative/future; append-only.
Latest valuation <= asOf wins by date DESC, created_at DESC, id DESC, never sum.
Backdated valuations affect their declared economic dates. Archiving is terminal,
idempotent, blocks metadata/valuation writes and excludes the item from that day's
end position onward; positions before archive retain it. No public delete/restore.

Money uses JSON integer strings and exact BigInt/numeric aggregation. Individual
values fit positive BIGINT; aggregate totals can exceed BIGINT without truncation.
Currency exponents 0/2/3 follow MDL2. Never combine different currencies.

## API, security and performance

JWT-protected `/api/v1/finance/net-worth`: GET summary (`asOf?`) and GET `/history`
(`currency`, `from`, `to`: inclusive YYYY-MM, <=60 months, no future). Closed months
use month end; current month uses profile today. Summary includes explanatory
ACCOUNT/MANUAL components, signed values, assets/liabilities/net per currency.

`/items`: GET filtered by kind/status/currency/category and POST atomic create.
`/items/:itemId`: GET/PATCH. POST `/archive`. GET/POST `/valuations`.
Strict TypeBox boundaries; owner only JWT.sub; foreign item returns 404.
Items page default50/max100, cursor createdAt+id. Valuations cursor includes
valuationDate+createdAt+id. Summary probes10001 components and returns409 above10000.
History aggregates all <=60 points in one bounded SQL statement with owner-filtered
movements and indexed lateral latest valuations; no month/item query N+1.
Read timeouts remain bounded by existing pool configuration.

Migration `0007_financial_net_worth` is generated by the existing offline Drizzle
workflow. Adds only two tables, compound FK, indexes, checks and RLS policies.
Private app schema is not exposed through Data API. RLS SELECT/INSERT/UPDATE on
items includes USING/WITH CHECK; valuations SELECT/INSERT only and insert requires
owned ACTIVE item. No DELETE policy, new hosted grants or changes to prior SQL.
